# C5: Surfaces (issue page, PR body) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The incident page and the PR body both read impact-first — impact badge + title, the server-rendered story line, coverage-proven recordings, the cause, then the receipt (one of the four frozen states) — with the PR body's verification section rendering **every** executed ledger check plus the not-run list, and every pre-existing PR-body section preserved.

**Architecture:** The incident DTO (`handler/read_api.go`) gains the C3 impact columns, a `story` string rendered server-side by `narrative.Story` (the single copy source C4 established), a derived `receipt_state`/`receipt_line` pair (detail endpoint only, derived after the brief loads so copy never claims an absent report), and a `recordings` list from a new coverage-gated query that aggregates per-session crash counts **before** any chunk access. The Vue incident view reorders around those fields. On the worker, `getErrorGroup` gains the impact columns, a TS mirror of the coverage-gated watchable-session query supplies the watch link (best-effort — a replay lookup failure costs the link, never the PR), and `buildPRBody` gains a leading "What users hit" section while its verification renderer expands from latest-per-role to every-ledger-entry. No migration; every column read here was frozen in 044 and stamped by C3.

**Tech Stack:** Go 1.24 (`packages/ingestion`: `handler`, `db`, `narrative`), Vue 3 + Vitest/jsdom (`packages/dashboard`), TypeScript Node 22 (`packages/worker`), Postgres (read-only against existing schema).

**Parent:** `docs/superpowers/plans/2026-08-10-unified-actionable-program-plan.md` §C5. Authority: `docs/design/2026-08-10-unified-actionable-program.md` (decisions 2, 5, 7 and the copy rule). Carried-forward detail: `docs/superpowers/plans/2026-08-10-actionable-receipts-v1.md` Tasks D1/D2 and `docs/design/2026-08-10-actionable-receipts.md` §5e, amended below (see "Deviations from carried-forward text").

## Global Constraints

- Postgres queue only; wire contract append-only (`test-fixtures/wire/` untouched — the diff check runs anyway); lease and terminal-status contracts preserved; human-trigger bypass untouched. **No new migration** — C5 is read-and-render only.
- **Copy rule (program, precise):** every customer-visible sentence C5 adds is a template over stored fields, owned by `narrative` (Go) with the PR body's TS mirror pinned to identical vectors (Deviation 4). `root_cause` and `agent_task_brief` are model-authored technical reports: they render only under investigation-output labels (the existing "Root Cause" / "Investigation output — agent task brief" sections), never interpolated into story or receipt lines. Receipt lines assert only stored facts and carry **no location words** ("below"/"attached") — the page's own layout is not a stored fact. Judge prose renders only inside `### Judge review` (PR body) — C5 moves sections, it never re-homes model prose.
- **No judgment-based impact labels:** the story line renders stored impact numbers or the exact phrase `recording impact unavailable`; the impact badge and the DTO's impact fields surface **only when the full tuple passes `narrative` validity** (one decider — a corrupt tuple renders the unavailable phrase *and* no badge, never a badge over an unavailable story).
- **One gate, all four states:** `receipt_state` requires readiness `eligible` for **every** state — an ineligible or pending incident gets no receipt framing regardless of artifacts (the honest state is the fallback surface). A real PR on such an incident still renders as a plain PR link (an artifact fact), without the receipt line.
- **Recordings never multiply counts:** per-session crash counts are aggregated from `error_events` before any chunk access; chunk data appears only inside `watchCoverageSQL`'s `EXISTS` probes and a span LATERAL that reads no event rows. The six-chunk test is the witness (AC5.4).
- **A recordings row proves coverage:** the list reuses `watchCoverageSQL` verbatim — a session that cannot play at its anchor is absent, not dead-linked (C3's rule).
- **PR-body markers frozen:** `VERIFICATION_START/END` and `CI_STATUS_START/END` survive the reorder byte-identical as delimiters; judge prose stays outside the CI sub-block (`pr.test.ts:456` keeps passing); `replaceCIStatusSection` surgery is unaffected.
- **Frozen receipt-state vocabulary** (C4): `'pr_open'`, `'attempt_failed_with_diff'`, `'attempt_failed_no_diff'`, `'report_ready'`. C5 adds no fifth state.
- **Supplementary lookups are best-effort:** the recordings attach (handler) and the watch-link lookup (worker) each catch their own failures, log, and omit — a replay-store or query hiccup never costs the page or the PR.
- Model-prose rendering discipline in Vue: `v-text`/`<pre>`, never `v-html`; PR links pass `safeUrl(..., GITHUB_PR_URL_OPTIONS)` (`IncidentDetail.vue:31`); session links are router-links, never raw hrefs.
- DTO changes are optional/`omitempty` additions except `story` (always present — the unavailable phrase is a value, not an absence). The list endpoint shares `toIncidentJSON`; `receipt_state`/`receipt_line`/`recordings`/brief are detail-only (derived where the brief is loaded), impact + story render on both.
- Go tests may not skip beyond the `check-go-skips.mjs` allowlist; dashboard component tests use the `// @vitest-environment jsdom` + `vi.mock('../../api')` harness (`incident-detail-honest-state.test.ts` is the template); worker DB-gated tests follow `db.test.ts` convention.
- Server-side packages stay AGPL-3.0-only.

## Deviations from carried-forward text (each deliberate, source-verified)

1. **Recordings rows carry `session_id` + `anchor_ms`, not a `url`.** D1 specified `recordings: [{…, url}]`. The dashboard already builds session router-links client-side (`IncidentDetail.vue:385-392`, `{name:'session-detail', query:{t}}`), and `handler.Dependencies` carries no dashboard base URL — absolute URLs are a Slack/PR need (external surfaces), not an SPA need. The digest keeps `sessionURLAt`; the page keeps router-links; both obey the same `?t=` epoch-ms contract.
2. **The recordings list is error-kind v1.** Friction incidents keep the C3 session-pointer player (AC3.5's surface, already shipped and witnessed playing); their signal-session recordings list is friction-lane presentation work (Stream B / post-program). D1 predates the kind split. The story line and receipt states render for both kinds. The friction pointer stays deliberately identity-based (C3's recorded design — the windowed player carries its own not-ready fallback); C5 does not relitigate that.
3. **`suggested_mitigation` is not added to the PR body.** D2 listed it; program decision 6 dropped `suggested_direction` because the brief subsumes it, and the PR body's "The fix" already renders the fix narrative from the attempt itself. Adding a legacy prose column to a reordered body would widen model-prose surface for nothing. (The issue page keeps rendering it where it already does — no change either way.)
4. **The story template exists twice, pinned to one language-neutral vector fixture.** R7 says "one template source." The issue page's `story` is server-rendered by Go `narrative.Story` — one source for the customer surface. The PR body is TypeScript and developer-facing; a cross-language RPC to render one sentence is not worth it. `storyLine` in `worker/src/narrative.ts` mirrors the Go template, and **both suites load the same JSON vector file** (`test-fixtures/story-vectors.json` — the C6 cross-language-golden pattern), so a vector change that lands on one side only fails the other side's test mechanically; duplicated-and-commented tables would rot silently. The same trade C2 made for `getGroupImpactBar`'s `bool_and` semantics.
5. **The verification section changes from latest-per-role to every-entry.** Today `buildLedgerLines` (`pr.ts:383-412`) renders only the newest entry per `LedgerRole` and silently drops every other executed command. AC5.5 says "verification lists every executed check + not-run list" — that is a behavior change to C2's renderer, made here deliberately, keeping the role entries' exact phrasing (the ci-watch byte-stability contract binds the *markers and role lines*, which are preserved verbatim) and adding plain lines for non-role entries with their `truncated`/`timedOut`/`workdirDirty` flags rendered, not hidden. Entries render sorted by `entrySeq` (sorted defensively in the renderer — input order is an implementation detail of the recorder, not a contract).
6. **The PR-body watch link is coverage-gated via a TS mirror of the Go SQL.** `db.getSessionPointerForGroup` (`db.ts:1797-1838`) resolves identity without chunk readiness — a link built from it can point at an unplayable session, which AC5.5's "watch link omitted" leg exists to prevent. `getWatchableSessionForGroup` copies `watchableErrorSessionSQL`/`watchableFrictionSessionSQL` + `watchCoverageSQL` (`sessions_read.go:339-404`) with a source-file cross-reference comment; precedent: the worker already mirrors the pointer query and the impact-bar semantics. Parity is pinned by the same three fixture shapes C3 used (three stitched chunks → link; 1ms chunk → none; no full snapshot → none). The lookup is wrapped in its own try/catch in `index.ts` — a failure logs and omits the link, never fails the fix job.
7. **`receipt_state` derives in `GetIncident`, after the brief loads, gated on eligibility for every state.** C4 derives the digest's state in SQL (post-eligibility, belt-checked); the page derives it in Go — but in the detail handler, not `toIncidentJSON`, so the report-backed states can require the report they claim: `attempt_failed_no_diff` and `report_ready` demand eligible readiness **and** a present (trimmed non-empty) `root_cause` or brief; `pr_open` and `attempt_failed_with_diff` demand eligible readiness **and** their artifact (`pr_open`'s URL must parse as http(s) — `safeUrl` stays the render gate, but the receipt line never claims a PR the link layer would refuse). Ineligible/pending incidents get no receipt framing whatever artifacts exist — with one honest nuance: a real PR's link still renders as a plain artifact fact (the PR exists; the receipt framing is what eligibility earns). Two spellings of one mapping is the C4-accepted pattern (its own SQL/Go `publishable` pair); both are pinned to the four frozen states by tests, and the page's test table covers in-flight, unknown, and closed statuses so the spellings cannot drift silently. A shared `narrative` home is deferred until a third consumer exists.
   **Recorded asymmetry vs C4's belt, deliberate:** the digest's report-backed states additionally require the structural validated-diagnosis predicate (citation-shaped evidence) because cards push model-prose *excerpts* into Slack; the page requires the report to be *present on the response* because the page IS where the report renders — C1 already decided what an eligible incident may show there. An incident held back from the digest belt (legacy eligible row, no citation-shaped decision) can therefore read `report_ready` on its own page. That is the pull-vs-push split the program's honest-surface decision encodes, not drift; the drift pin is the status/eligibility table, which both spellings share.
   **Stale-artifact nuance, recorded:** `attempt_failed_with_diff` reflects group-level artifacts (`candidate_diff` as last persisted), not per-attempt provenance — if the newest attempt saved no diff but an older one did, the page shows the older saved diff under the failed-attempt line. Group-level artifact truth is C2's persistence model; per-attempt artifact history is out of C5's scope.
8. **AC5.6's "pre-branch capture" is materialized first, and the guard compares section bodies.** No captured PR body exists anywhere in the repo. Task 6 renders `buildPRBody` — the *unmodified* C2 code — over a canonical full-featured human-triggered input and commits the output as a fixture **before any reorder commit**; the guard test splits the capture into sections by heading and asserts each section's whitespace-normalized **body** (not just its heading) still appears in the new output. The capture is of the code path, not of a live GitHub PR; a prod PR body would embed customer data a fixture must not.
9. **The list endpoint gains impact fields and `story` as a side effect; receipts stay detail-only.** `toIncidentJSON` serves list and detail (`read_api.go:288/:314/:593/:899`); the impact columns and `has_saved_diff` boolean are added to both SELECTs (plain columns, no join cost), so list rows carry an honest story too. `receipt_state`/`receipt_line` derive only in `GetIncident` (they need the brief-presence check), and `recordings` stays detail-only (per-row subqueries don't belong in a list). This is scope the program's C5 line doesn't name, accepted because the alternative — a wrong "unavailable" story on list rows — is a copy-rule violation.
10. **`duration_ms` is the recorded span, gaps included.** C3's coverage contract accepts intra-span gaps in v1 (recorded there); `max(last_event_ms) − min(first_event_ms)` inherits that. The field is documented as "recorded span" in both type mirrors; computing gap-free covered duration is post-program work if the spans mislead anyone.
11. **Recording rows anchor on the session's newest *ingested* occurrence (its client timestamp); the list orders by that client-time anchor.** Same convention as `watchableErrorSessionSQL` (`ORDER BY created_at` picks the occurrence, the `?t=` anchor is client-clock). Under client clock skew the display order may disagree with arrival order — accepted; the anchor's job is to seek the player, not to define recency.

```go
// GroupRecording is one watchable session on an error incident's page:
// coverage-proven at its anchor (the client timestamp of the session's newest
// ingested occurrence of this group — the watchableErrorSessionSQL
// convention), with the crash count aggregated from error_events alone so
// chunk multiplicity can never inflate it.
type GroupRecording struct {
	SessionID  string
	StartedAt  time.Time
	DurationMs int64 // RECORDED SPAN of scrubbed bounded chunks (gaps included, C3's v1 trade): max(last_event_ms) - min(first_event_ms)
	CrashCount int64 // this group's events in this session
	AnchorMs   int64 // absolute client-clock epoch ms, the dashboard ?t= contract
}

const recordingsCap = 5

// RecordingsForGroup lists watchable sessions for an error-kind incident,
// newest anchor first, capped at recordingsCap. Friction incidents return nil
// (their page keeps the C3 session-pointer player).
func (q *Queries) RecordingsForGroup(ctx context.Context, errorGroupID, projectID string) ([]GroupRecording, error)
```

  The query — the candidate block is `watchableErrorSessionSQL`'s **verbatim** (same `DISTINCT ON` + newest-`watchCandidateEvents` pool, the access shape C3 shipped; if its plan was acceptable for every digest build, one page load is too), with the outer `LIMIT 1` replaced by two LATERALs that read no chunk row into any count:

```go
var groupRecordingsSQL = fmt.Sprintf(`
SELECT cand.session_id, cand.started_at, crashes.crash_count, cand.anchor_ms,
       span.first_ms, span.last_ms
  FROM (
    SELECT per_session.* FROM (
      SELECT DISTINCT ON (e.session_id)
             e.session_id,
             (extract(epoch FROM e."timestamp") * 1000)::bigint AS anchor_ms,
             e.created_at, e.id, s.started_at
        FROM error_events e
        JOIN sessions s ON s.id = e.session_id AND s.project_id = e.project_id
       WHERE e.error_group_id = $1 AND e.project_id = $2
         AND e.session_id IS NOT NULL AND s.status <> 'deleting'
       ORDER BY e.session_id, e.created_at DESC, e.id DESC
    ) per_session
    ORDER BY per_session.created_at DESC, per_session.id DESC
    LIMIT %d
  ) cand
  CROSS JOIN LATERAL (
    SELECT count(*)::bigint AS crash_count
      FROM error_events e
     WHERE e.error_group_id = $1 AND e.project_id = $2
       AND e.session_id = cand.session_id
  ) crashes
  CROSS JOIN LATERAL (
    SELECT min(c.first_event_ms) AS first_ms, max(c.last_event_ms) AS last_ms
      FROM session_chunks c
     WHERE c.session_id = cand.session_id AND c.project_id = $2
       AND c.scrubbed_at IS NOT NULL
       AND c.first_event_ms IS NOT NULL AND c.last_event_ms IS NOT NULL
  ) span
  %s
  ORDER BY cand.anchor_ms DESC, cand.session_id DESC
  LIMIT %d`, watchCandidateEvents, watchCoverageSQL, recordingsCap)
```

  `DurationMs = last_ms - first_ms` computed in Go from the span columns (never NULL for a kept row — `watchCoverageSQL`'s first `EXISTS` guarantees bounded chunks exist). The function first calls `groupKind` and returns `nil, nil` for friction. Crash counts come from the `crashes` LATERAL over `error_events` only — the chunk table appears solely in `span` (an aggregate over a different table) and in `watchCoverageSQL`'s `EXISTS` probes, so a session with 6 covering chunks reports exactly its event count; the six-chunk test is the witness (AC5.4). Ordering vs anchoring: candidates are the newest-ingested per session; display order is by client-time anchor (Deviation 11).
