# Friction Signal Insert Race Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop concurrent friction match jobs for the same session from failing with a duplicate-key error when they write the same observation signal.

**Architecture:** `writeObservationSignals` inserts each observation with `ON CONFLICT (session_id, narrative_id, observation_id) ... DO NOTHING`. `friction_signals` has a second unique constraint, `(session_id, fingerprint, rule_version)`. For rows built by `buildSignalRows`, the fingerprint is a hash of the same session, narrative and observation. When two writers race, the second one can hit the fingerprint constraint first. That constraint is not the conflict target, so PostgreSQL raises an error instead of doing nothing. The fix drops the conflict target so `DO NOTHING` covers every unique constraint. The existing fallback `SELECT` then returns the winner's row, and still throws if the requested observation is absent.

**Tech Stack:** TypeScript (Node 22, ESM), `pg`, Vitest, PostgreSQL 16 (pgvector image).

**Spec:** This plan has no separate spec. The Problem section below is the specification. It was revised after a Codex review on 2026-09-15.

## Revision after pre-landing review (2026-09-15)

Two test changes were made on top of Task 1:
- **`persist.integration.test.ts`** has a new case, `throws instead of returning another row when only the fingerprint collides`. It pins the lookup that refuses to report another observation's row. A mutation check confirmed that it fails if that `throw` is removed.
- **`persist-concurrency.integration.test.ts`** now checks out its connections with `Promise.allSettled`. If only some checkouts succeed, it releases those connections before failing, so teardown can't hang.

## Problem

- **CI:** `packages/worker/src/friction/__tests__/match-job.integration.test.ts > serializes concurrent decisions on the same signal without duplicate creation` failed twice (CI runs 34734944069 on 2026-09-13 and 35028705952 on main on 2026-09-15) with `duplicate key value violates unique constraint "friction_signals_session_id_fingerprint_rule_version_key"` at `persist.ts:27`.
- **Unique keys:** `friction_signals` has exactly three:

  | Key | Columns | Defined at |
  |---|---|---|
  | Primary key | `(id)`, generated by `gen_random_uuid()` | `004_friction.sql:36` |
  | `friction_signals_session_id_fingerprint_rule_version_key` | `(session_id, fingerprint, rule_version)` | `004_friction.sql:61` |
  | `idx_friction_signals_atomic` | `(session_id, narrative_id, observation_id) WHERE observation_id IS NOT NULL` | `078_friction_tickets.sql:41` |

  Only `idx_friction_signals_atomic` is the conflict target today.
- **Fingerprint:** `packages/worker/src/narrative/emit.ts:50` computes `createHash('sha256').update(`${sessionId}|${narrativeId}|${observation.id}`)`, truncated to 128 bits. For rows from `buildSignalRows` (the only production input, through `friction/match-job.ts:221` and `db.ts`), both non-primary keys identify the same logical row.
- **The schema does not require that equivalence.** A row with the same session, fingerprint and `rule_version` 7 but a different or NULL observation would also be absorbed. The fallback `SELECT` (`persist.ts:58-63`) would then not find the requested observation and would throw `Observation signal ... missing after insert`. So the fix never reports success for a row it did not store. Legacy rule signals use a different `rule_version`, so they cannot conflict.
- **PostgreSQL behavior:** `ON CONFLICT ... DO NOTHING` with a conflict target absorbs conflicts only on that target. A concurrent conflict on any other unique index raises `23505`. With no conflict target, every unique constraint is covered.
- **Measured on a disposable pg16 database:** 300 rounds of 4 concurrent writers on one observation produced 215 `23505` errors with the current clause and 0 with `ON CONFLICT DO NOTHING`.
- **Production impact:** two match jobs for one session that overlap (for example a reclaimed lease) fail one job with a retryable error. No duplicate rows are written.

- [ ] **Step 2: Write the concurrency regression test**

Create `packages/worker/src/friction/__tests__/persist-concurrency.integration.test.ts`:

```ts
import { randomUUID } from 'node:crypto';
import pg from 'pg';
import { afterAll, beforeAll, describe, expect, it } from 'vitest';
import { buildSignalRows, deriveNarrativeId } from '../../narrative/emit.js';
import type { SessionRow } from '../../db.js';
import { writeObservationSignals } from '../persist.js';

const describeDb = process.env['DATABASE_URL'] ? describe : describe.skip;

type Written = Awaited<ReturnType<typeof writeObservationSignals>>;

// Concurrent writers must commit on separate connections, so this suite cannot
// share the rolled-back transaction that persist.integration.test.ts uses.
describeDb('atomic observation persistence under concurrent writers', () => {
  // Timing-dependent, not a deterministic reproduction. Before the fix, 4
  // writers started together raised the duplicate-key error in most rounds, so
  // 25 rounds failed on every measured run.
  const ROUNDS = 25;
  const WRITERS = 4;
  let pool: pg.Pool;
  let orgId: string | undefined;
  let projectId: string | undefined;
  let environmentId: string;

  beforeAll(async () => {
    pool = new pg.Pool({ connectionString: process.env['DATABASE_URL'], max: WRITERS + 2 });
    orgId = (await pool.query<{ id: string }>(
      `INSERT INTO orgs (name) VALUES ('persist-concurrency-test') RETURNING id`,
    )).rows[0]!.id;
    projectId = (await pool.query<{ id: string }>(
      `INSERT INTO projects (org_id, name) VALUES ($1, 'persist-concurrency') RETURNING id`, [orgId],
    )).rows[0]!.id;
    environmentId = (await pool.query<{ id: string }>(
      `INSERT INTO environments (project_id, name) VALUES ($1, 'production') RETURNING id`, [projectId],
    )).rows[0]!.id;
  });

  afterAll(async () => {
    try {
      if (projectId) {
        await pool.query('DELETE FROM friction_signals WHERE project_id = $1', [projectId]);
        await pool.query('DELETE FROM sessions WHERE project_id = $1', [projectId]);
        await pool.query('DELETE FROM environments WHERE project_id = $1', [projectId]);
        await pool.query('DELETE FROM projects WHERE id = $1', [projectId]);
        // Deleting a project writes a tombstone through a trigger (030_sourcemap_files.sql).
        await pool.query('DELETE FROM sourcemap_tombstones WHERE project_id = $1', [projectId]);
      }
      if (orgId) await pool.query('DELETE FROM orgs WHERE id = $1', [orgId]);
    } finally {
      await pool?.end();
    }
  });

  it('returns one shared signal per observation when writers race on the same narrative', async () => {
    for (let round = 0; round < ROUNDS; round++) {
      const session = (await pool.query<SessionRow>(
        `INSERT INTO sessions (id, project_id, environment_id, started_at)
         VALUES ($1, $2, $3, now()) RETURNING *, started_at::text`,
        [`race-${randomUUID()}`, projectId, environmentId],
      )).rows[0]!;
      const narrativeId = deriveNarrativeId(session.id, '2026-09-15 12:00:00.000001+00', 2);
      const rows = buildSignalRows(
        { startTs: 1_000, lines: [{ t: 'save', s: 'button.save', r: '/assets', a: 1_000 }] },
        [
          { id: 'o1', what: 'Save shows an error', evidenceLines: ['L1'] },
          { id: 'o2', what: 'Search repeats results', evidenceLines: ['L1'] },
        ],
        session.id,
        narrativeId,
      );
      // Check out every connection first, so all writers send their INSERTs together.
      const clients = await Promise.all(Array.from({ length: WRITERS }, () => pool.connect()));
      let settled: PromiseSettledResult<Written>[];
      try {
        // allSettled drains every writer before the connections are released.
        settled = await Promise.allSettled(
          clients.map((client) => writeObservationSignals(client, session, rows)),
        );
      } finally {
        for (const client of clients) client.release();
      }
      const failure = settled.find((result): result is PromiseRejectedResult => result.status === 'rejected');
      if (failure) throw failure.reason;
      const written = settled.map((result) => (result as PromiseFulfilledResult<Written>).value);
      for (const result of written) expect(result).toEqual(written[0]);
      const stored = await pool.query<{ n: number }>(
        'SELECT count(*)::int AS n FROM friction_signals WHERE session_id = $1', [session.id],
      );
      expect(stored.rows[0]!.n).toBe(2);
    }
  }, 60_000);
});
```
