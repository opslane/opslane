# Billing v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Outcome-priced billing via Autumn: Free/Pro plans keyed to merged fix PRs, quota gates in the worker, a billing sweeper that reports merges to Autumn, and a Settings billing tab — all a complete no-op unless `AUTUMN_SECRET_KEY` is set.

**Architecture:** Autumn (on Stripe) owns plans, metering math, checkout, and dunning. Our side: a Go `billing` package (client + sweeper) in ingestion, a small TS client in the worker for pre-spend quota checks, three admin HTTP routes proxying Autumn, and one new DB table (`billing_tracked`) making usage reporting idempotent. Merge detection reuses the existing GitHub webhook receipts (`pr_outcomes`) — no GitHub polling.

**Tech Stack:** Go 1.24 (net/http, pgx), Node 22 TypeScript (fetch), Vue 3, Autumn REST API (`https://api.useautumn.com`).

**Spec:** `docs/design/2026-09-01-billing-v1.md`

## Deviations from the spec (encode both in Task 9's doc amendment)

1. **Merge detection**: the spec says "a polling sweeper over open PRs using GitHub credentials." `handler/webhook.go` + `Queries.ProcessPRWebhook` (`packages/ingestion/db/queries.go:2460`) already record **durable, delivery-id-deduped merge receipts** in `pr_outcomes` (`004_friction.sql:73`, `fix_job_id` set for worker-opened PRs). Billing consumes those receipts; same requirement, zero new GitHub API surface. Accepted v1 risks, to be written into the design doc: (a) a missing/misconfigured webhook or a merge arriving before the worker records the PR under-bills — the spec's chosen failure direction; a reconciliation poller is an explicit fast-follow, not v1; (b) when two projects bind the same `github_repo`, `ProcessPRWebhook` matches one arbitrarily (documented in that function) — billing inherits this; acceptable because both projects are near-always in the same org, and the org is what's charged.
2. **Investigation cap enforcement point**: the spec says "at enqueue." There are three enqueue producers (worker inquiry-decision `db.ts:2287`, `friction/promotion.ts:132`, Go ingest `queries.go:1422`) and the Go one is the event hot path where a synchronous Autumn call is unacceptable. The gate moves to worker claim time (`processInvestigateJob`), the single place all investigate jobs pass through, before any LLM spend. Consequence to state honestly in the design doc: an over-cap group's investigate job completes as a no-op and **is not automatically re-run next month** — the group stays visible in triage and a `investigation_quota_skipped` usage event fires; re-investigation happens only via the existing human re-trigger paths.

## Global Constraints

- Billing is enabled iff `AUTUMN_SECRET_KEY` is non-empty **after trimming whitespace, in both runtimes** (Go `strings.TrimSpace`, TS `.trim()`). Unset ⇒ zero Autumn calls, no limits, no billing routes (404), no billing tab.
- Fail-open invariant (spec): production-path quota `check` failures (network, 5xx, timeout) return **allowed**; usage `track` failures are retried by the sweeper, never block anything, and log one line. The **billing summary endpoint is the deliberate exception**: it is strict and returns 502 on provider failure, because a settings page silently showing empty balances is a lie, not resilience.
- Autumn feature IDs: `merged_prs`, `investigations`. Plan IDs: `free`, `pro` (env-overridable). Customer ID = `orgs.id` (the active org). Value amounts: always 1.
- **Autumn API paths are unverified-in-anger**: two doc sources disagree (`docs.useautumn.com/api-reference/*` says `POST /customers`, `/v1/balances.check`, `/v1/balances.track`, `/v1/billing.attach`, `/v1/billing.open_customer_portal`; older guide pages say `/v1/track`, `/v1/customers`, `/v1/customers/{id}/billing_portal`). Every path lives in exactly one constants block per runtime (Go `billing/client.go`, TS `billing.ts`), and Task 2 Step 0 verifies the real paths against the Autumn **sandbox** with `curl` before any code is written. If paths differ from this plan, fix the constants and the test fixtures — nothing else should change.
- Billable-unit identity is **stable PR identity, not webhook delivery id**: ref = `pr:<project_id>:<github_repo>:<pr_number>` (repo lowercased; Task 1 adds a `github_repo` column to `pr_outcomes` so the identity survives a project being rebound to a different repository whose PR numbers restart). GitHub manual redelivery mints fresh delivery ids and `recoverReopenedMerge` can insert a second `merged` receipt for the same PR — the stable ref makes both bill exactly once.
- **Cross-org repo collisions are never billed silently**: when the same `github_repo` is bound to projects in more than one org, `ProcessPRWebhook`'s match is arbitrary (documented in that function) and could attribute a merge to the wrong org. The sweeper excludes those receipts from billing and emits a `billing_ambiguous_org` usage event for manual operator handling instead of charging a possibly-wrong customer.
- **Deploy coupling**: the 070 backfill settles history at migration time, so the cloud deploy that applies 070 must set `AUTUMN_SECRET_KEY` in the same rollout. A gap between migration and key activation leaves that window's merges unsettled and they will bill on activation — acceptable only if the gap is hours, not weeks.
- Ingestion: handlers in `handler/`, DB ops in `db/`; every DB helper scoped by project/org in its query; migrations append-only, idempotent, next number is `070`.
- Env vars must be read via literal `os.Getenv("X")` / `process.env['X']` (docs-drift regexes). **Each task that introduces an env read updates `docs/reference/environment-variables.md`, `.env.example`, and `docker-compose.yml` in that same task** — `pnpm test:repo` must be green after every task, not just Task 9. Same for routes (`docs/reference/http-routes.md`) and reason codes (`docs/reference/reason-codes.md`, which the drift checker validates against the `ReasonCode` union including its count).
- Go CI fails on any skipped test (`check-go-skips.mjs`); worker DB suites use `describe.skipIf(!process.env['DATABASE_URL'])` and `*.integration.test.ts` naming; Vitest tests colocated per existing convention (`Settings.test.ts` sits beside the view — verified present).
- ESM + strict TypeScript; `unknown` + narrowing, never `any`. AGPL-3.0-only for all packages touched except `shared` (MIT — the one `ReasonCode` addition there is intentional: it's part of the public incident contract).
- Do not weaken terminal-status or lease contracts. Do not touch frozen wire fixtures.

```sql
-- 070_billing_tracked.sql
-- Billing v1 (docs/design/2026-09-01-billing-v1.md): dispatch ledger for
-- billing-related side effects. One row per dispatched unit, keyed by a stable
-- natural ref:
--   'pr:<project_id>:<github_repo>:<pr_number>'  merged-PR usage reported to Autumn
--   'sessions_alert:<org_id>:<YYYY-MM>'          monthly session-ceiling Slack alert
--   'launch:backfill'                            one-shot sentinel (see below)
-- Insert-once semantics make the billing sweeper safe to crash and re-run.
-- For 'pr:' refs a row means Autumn durably accepted (or deduped) the track
-- call; for alert refs it means the alert was dispatched best-effort.
CREATE TABLE IF NOT EXISTS billing_tracked (
  ref        TEXT PRIMARY KEY,
  org_id     UUID REFERENCES orgs(id),
  feature_id TEXT NOT NULL CHECK (feature_id <> ''),
  value      NUMERIC(12,4) NOT NULL DEFAULT 1,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_billing_tracked_org ON billing_tracked(org_id);

-- Repo identity on receipts: PR numbers restart when a project is rebound to
-- a different repository, so the billing ref needs the repo. Nullable —
-- pre-070 receipts have no repo; the backfill settles them anyway.
ALTER TABLE pr_outcomes ADD COLUMN IF NOT EXISTS github_repo TEXT;

-- Launch cutoff: merges that happened before billing existed are settled as
-- already-tracked (value 0) so the first sweep cannot back-bill history into
-- the current Autumn period. One-shot: guarded by the 'launch:backfill'
-- sentinel row (an empty table is NOT a durable "already ran" signal — zero
-- historical merges would re-arm the backfill on every boot and zero-settle
-- live merges). Advisory lock guards concurrent boots.
BEGIN;
SELECT pg_advisory_xact_lock(hashtext('070_billing_tracked'));
INSERT INTO billing_tracked (ref, org_id, feature_id, value)
SELECT DISTINCT ON (po.project_id, po.pr_number)
       'pr:' || po.project_id || ':' || lower(coalesce(po.github_repo, p.github_repo, '')) || ':' || po.pr_number,
       p.org_id, 'merged_prs', 0
FROM pr_outcomes po
JOIN projects p ON p.id = po.project_id
WHERE po.outcome = 'merged' AND po.fix_job_id IS NOT NULL
  AND NOT EXISTS (SELECT 1 FROM billing_tracked WHERE ref = 'launch:backfill')
ON CONFLICT (ref) DO NOTHING;
INSERT INTO billing_tracked (ref, org_id, feature_id, value)
VALUES ('launch:backfill', NULL, 'sentinel', 0)
ON CONFLICT (ref) DO NOTHING;
COMMIT;
```

```go
package db

type UnbilledMergedPR struct {
	Ref        string
	PRNumber   int
	OrgID      string
	OrgName    string
	OccurredAt time.Time
}

// ListUnbilledMergedPRs returns worker-opened merged-PR receipts not yet
// reported to Autumn, one per stable PR identity. fix_job_id IS NOT NULL
// excludes human/MCP-linked PRs (design 2026-09-01). DISTINCT ON collapses
// duplicate receipts for the same PR (GitHub manual redelivery mints fresh
// delivery ids; recoverReopenedMerge can insert a second merged receipt).
// Receipts whose repo is bound to projects in more than one org are excluded
// (Ambiguous=true) — ProcessPRWebhook's match is arbitrary there and billing
// a possibly-wrong org is worse than alerting the operator.
func (q *Queries) ListUnbilledMergedPRs(ctx context.Context, limit int) ([]UnbilledMergedPR, error) {
	rows, err := q.pool.Query(ctx, `
		SELECT DISTINCT ON (po.project_id, po.pr_number)
		       'pr:' || po.project_id || ':' || lower(coalesce(po.github_repo, p.github_repo, '')) || ':' || po.pr_number,
		       po.pr_number, p.org_id, o.name, po.occurred_at,
		       EXISTS (
		         SELECT 1 FROM projects p2
		         WHERE lower(p2.github_repo) = lower(p.github_repo)
		           AND p2.org_id <> p.org_id
		       ) AS ambiguous
		FROM pr_outcomes po
		JOIN projects p ON p.id = po.project_id
		JOIN orgs o ON o.id = p.org_id
		WHERE po.outcome = 'merged'
		  AND po.fix_job_id IS NOT NULL
		  AND NOT EXISTS (
		    SELECT 1 FROM billing_tracked bt
		    WHERE bt.ref = 'pr:' || po.project_id || ':' || lower(coalesce(po.github_repo, p.github_repo, '')) || ':' || po.pr_number
		  )
		ORDER BY po.project_id, po.pr_number, po.occurred_at, po.created_at, po.id
		LIMIT $1`, limit)
	// scan into []UnbilledMergedPR (Ambiguous bool field included), return
}

func (q *Queries) MarkBillingTracked(ctx context.Context, ref, orgID, featureID string, value float64) (bool, error) {
	ct, err := q.pool.Exec(ctx, `
		INSERT INTO billing_tracked (ref, org_id, feature_id, value)
		VALUES ($1, $2, $3, $4) ON CONFLICT (ref) DO NOTHING`,
		ref, orgID, featureID, value)
	if err != nil {
		return false, err
	}
	return ct.RowsAffected() > 0, nil
}

// OrgSessionCountsThisMonth: current-calendar-month session counts per org,
// only orgs over threshold. Alerting-grade, not billing-grade: projects with
// retention shorter than a month undercount (accepted; see design doc).
func (q *Queries) OrgSessionCountsThisMonth(ctx context.Context, threshold int) (map[string]int, error) {
	rows, err := q.pool.Query(ctx, `
		SELECT p.org_id, count(*)
		FROM sessions s JOIN projects p ON p.id = s.project_id
		WHERE s.created_at >= date_trunc('month', now())
		GROUP BY p.org_id
		HAVING count(*) > $1`, threshold)
	// scan into map[string]int, return
}
```

- [ ] **Step 3: Implement `sweeper.go`** (retention.go template: `Start` = one immediate pass, ticker, ctx.Done; `runPass` logs, never returns error):

```go
func (s *Sweeper) RunOnce(ctx context.Context) (int, error) {
	if s.Q == nil || s.Client == nil { return 0, errors.New("billing sweeper not configured") }
	prs, err := s.Q.ListUnbilledMergedPRs(ctx, 100)
	if err != nil { return 0, err }
	billed := 0
	var firstErr error
	for _, pr := range prs {
		if pr.Ambiguous {
			// Repo bound in >1 org: ProcessPRWebhook's match is arbitrary, so
			// billing could charge the wrong customer. Alert once (ledger-deduped)
			// and leave the receipt unbilled for manual handling.
			if ins, _ := s.Q.MarkBillingTracked(ctx, "ambiguous:"+pr.Ref, pr.OrgID, "ambiguous_org", 0); ins {
				usageevents.Emit("billing_ambiguous_org", map[string]string{"org_id": pr.OrgID, "ref": pr.Ref})
			}
			continue
		}
		if _, err := s.Client.EnsureCustomer(ctx, pr.OrgID, pr.OrgName); err != nil {
			if firstErr == nil { firstErr = err }
			continue
		}
		if err := s.Client.Track(ctx, pr.OrgID, "merged_prs", pr.Ref, 1, pr.OccurredAt); err != nil {
			if firstErr == nil { firstErr = err }
			continue // not marked; next pass retries with the same idempotency ref
		}
		inserted, err := s.Q.MarkBillingTracked(ctx, pr.Ref, pr.OrgID, "merged_prs", 1)
		if err != nil {
			if firstErr == nil { firstErr = err }
			continue // Autumn has it; the 409/idempotency_key path absorbs the re-track
		}
		if !inserted {
			continue // a concurrent replica won the insert; it owns the emit and count
		}
		usageevents.Emit("billable_pr_merged", map[string]string{"org_id": pr.OrgID, "pr": strconv.Itoa(pr.PRNumber)})
		billed++
	}
	s.alertSessionCeilings(ctx)
	return billed, firstErr
}

// alertSessionCeilings: track-only v1 (design doc). One Slack alert per org
// per calendar month, deduped through the billing_tracked dispatch ledger.

// acceptable operator noise until enforcement exists. Emit is fire-and-forget;
// a dropped Slack message loses that month's alert (accepted for alerting).
func (s *Sweeper) alertSessionCeilings(ctx context.Context) {
	threshold := s.SessionAlertThreshold
	if threshold <= 0 { threshold = 5000 }
	over, err := s.Q.OrgSessionCountsThisMonth(ctx, threshold)
	if err != nil { slog.Error("billing: session ceiling scan failed", "error", err); return }
	for orgID, n := range over {
		ref := fmt.Sprintf("sessions_alert:%s:%s", orgID, time.Now().UTC().Format("2006-01"))
		inserted, err := s.Q.MarkBillingTracked(ctx, ref, orgID, "sessions_alert", float64(n))
		if err != nil || !inserted { continue }
		usageevents.Emit("session_ceiling_exceeded", map[string]string{"org_id": orgID, "sessions": strconv.Itoa(n)})
	}
}
```

```ts
const DEFAULT_BASE = 'https://api.useautumn.com';
// Paths verified against the Autumn sandbox in Task 2 Step 0 — keep in sync
// with packages/ingestion/billing/client.go.
const PATH_CUSTOMERS = '/customers';
const PATH_CHECK = '/v1/balances.check';

export function billingEnabled(): boolean {
  return Boolean(process.env['AUTUMN_SECRET_KEY']?.trim());
}

// Compose sets optional vars as present-but-empty (`${NAME:-}`), so `??` would
// happily keep "" — trim-then-|| is the only correct fallback shape here.
function envOr(name: string, fallback: string): string {
  return (process.env[name] ?? '').trim() || fallback;
}

async function autumnPost(path: string, body: Record<string, unknown>): Promise<Response> {
  const base = envOr('AUTUMN_BASE_URL', DEFAULT_BASE).replace(/\/+$/, '');
  return fetch(`${base}${path}`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${process.env['AUTUMN_SECRET_KEY']?.trim() ?? ''}`,
    },
    body: JSON.stringify(body),
    signal: AbortSignal.timeout(5000),
  });
}

/** Fail-open by contract: billing must never block investigation or fix work. */
export async function checkQuota(
  orgId: string,
  orgName: string,
  featureId: 'merged_prs' | 'investigations',
  opts: { sendEvent?: boolean } = {}
): Promise<{ allowed: boolean; failedOpen: boolean }> {
  if (!billingEnabled()) return { allowed: true, failedOpen: false };
  try {
    const cust = await autumnPost(PATH_CUSTOMERS, {
      customer_id: orgId,
      name: orgName,
      auto_enable_plan_id: envOr('AUTUMN_FREE_PLAN_ID', 'free'),
    });
    if (!cust.ok) throw new Error(`autumn customers status ${cust.status}`);
    const res = await autumnPost(PATH_CHECK, {
      customer_id: orgId,
      feature_id: featureId,
      ...(opts.sendEvent ? { send_event: true } : {}),
    });
    if (!res.ok) throw new Error(`autumn check status ${res.status}`);
    const data: unknown = await res.json();
    // Malformed data must not silently deny (or allow-as-verdict): only a real
    // boolean is an answer; anything else is a marked fail-open.
    const allowedField =
      typeof data === 'object' && data !== null && 'allowed' in data
        ? (data as { allowed: unknown }).allowed
        : undefined;
    if (typeof allowedField !== 'boolean') {
      logger.warn('billing check malformed response; failing open', { feature: featureId });
      return { allowed: true, failedOpen: true };
    }
    return { allowed: allowedField, failedOpen: false };
  } catch (err: unknown) {
    logger.warn('billing check failed open', {
      feature: featureId,
      error: err instanceof Error ? err.message : String(err),
    });
    return { allowed: true, failedOpen: true };
  }
}
```
