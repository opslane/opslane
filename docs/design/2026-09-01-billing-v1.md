# Billing v1 — decisions

Date: 2026-09-01. Status: agreed; v1 code implemented, deployment prerequisites pending.

## Shape

Outcome-priced subscription via **Autumn** (on Stripe). The billable unit is **a PR opened
by the Opslane worker whose GitHub state becomes merged**. Costs scale with attempts
(LLM + sandbox), so unpriced fair-use ceilings protect the flat fee.

Measured basis (prod `job_usage`, 30 days to 2026-09-01): total LLM spend $12.45;
investigate avg $0.025/job (407 jobs); fix avg $0.31/job + E2B (5 jobs);
session_analysis 342,965 jobs at $0 recorded LLM cost (rule-based); session_narrate
83 jobs, **no ledger rows during the measured period — the implementation closes this
gap**. Comp: Lucent charges $499/mo for 10k sessions + 3 autofix PRs.

## Plans

| | Free | Pro |
|---|---|---|
| Price | $0 | **$149/mo** |
| Merged PRs included | 2/mo | 10/mo, then **$10/PR** overage (auto-billed) |
| Investigations (fair use, unpriced, quiet) | ~25/mo | ~250/mo |
| Sessions (fair use, track-only in v1) | ~5k/mo | ~30k/mo |
| Seats | unlimited | unlimited |

Enterprise = a contact-us link, not a plan. No annual billing, no storage/event
pricing, no seat pricing in v1. Every existing and new org defaults to Free silently;
no grandfathering; comp our own org. Autumn customer = `orgs.id` (the **active** org,
not `users.org_id`), created lazily on first billing touch.

## Billable-unit rules

- Only worker-opened PRs count. MCP-assisted fixes are never billed (attribution is
  unprovable, marginal cost ~0, MCP is distribution); base fee "includes" MCP access.
- Merged = billable, no clawbacks (revert still counts; disputes are a Stripe refund).
- Closed-unmerged = terminal, never billed.
- Bill on merge date (merge may land in a later period than creation).

## Merge detection

The ingestion GitHub webhook already writes durable, delivery-ID-deduplicated PR
state receipts to `pr_outcomes`. A billing sweeper reads merged receipts linked to
worker fix jobs; MCP-assisted and human PRs have no `fix_job_id` and remain excluded.
The stable billable-unit reference is
`pr:<project_id>:<lowercase_github_repo>:<pr_number>`, so a manual webhook redelivery
or a recovered reopened merge cannot charge twice. After Autumn accepts a `track()`
call, the sweeper inserts that reference into `billing_tracked`. A failed track leaves
the receipt eligible for the next pass, and Autumn receives the same idempotency key
on every retry.

This webhook-based design accepts under-billing as its failure direction. A missing
or misconfigured webhook, or a merge delivered before the worker records its PR,
leaves no billable receipt. A reconciliation poller over GitHub is an explicit
fast-follow, not part of v1.

`ProcessPRWebhook` chooses one project arbitrarily when several projects bind the
same `github_repo`. When those projects belong to one org, the arbitrary project
attribution does not change the customer charged. When they span orgs, the sweeper
does not bill the receipt; it emits a ledger-deduplicated `billing_ambiguous_org`
usage event for manual operator handling.

## Gating and failure

- **The flag is `AUTUMN_SECRET_KEY` presence** (convention: `USAGE_EVENTS_SLACK_WEBHOOK`).
  Unset (OSS/self-hosted/dev/CI): no Autumn calls, no limits, no billing tab —
  self-hosted gets the full product free with no nag, consciously. Not coupled to
  `cloudAuthEnabled()`/WorkOS. Dashboard learns billing-on via `/auth/config`.
- **Fail-open invariant**: Autumn down/erroring ⇒ `check()` allows. A failed `track()`
  leaves its receipt unmarked, logs the failure, and retries on a later sweep. Billing
  must never block ingestion or PR creation. The billing-summary endpoint is the
  deliberate exception: a provider failure returns 502 instead of showing incomplete
  balances as a successful response.

## Enforcement

1. **PR-creation gate (worker)**: `check(merged_prs)` before opening a PR. Free at
   limit ⇒ no PR; incident lands `needs_human` with an upgrade note. Pro is never
   blocked (overage bills). Overshoot from already-open PRs is accepted.
2. **Investigation cap (worker, at claim)**: every investigate job passes one gate
   before any LLM spend. An over-cap job completes as a no-op, emits an
   `investigation_quota_skipped` usage event, and leaves its group visible in triage.
   It does not resume automatically next month; only the existing human re-trigger
   paths schedule another investigation. The cap counts attempts: a lease loss or
   retry counts again because attempts consume money. This is acceptable for a
   fair-use cost ceiling.
3. **Sessions: track-only.** Over ceiling fires a usage event to Slack; nothing
   blocks. Enforcement is a fast-follow after seeing a real over-quota org.

Limit visibility in v1: the billing tab usage bars + the `needs_human` note. No
banners or emails (Stripe handles dunning).

## Cost invariant

**LLM session narration stays lazy** — only for sessions a human opens or an
investigation touches, never always-on per session. At ~$0.06/session and 10k–30k
sessions/mo, always-on narration is -$600–1,800/mo per customer. The session
ceilings exist as the backstop if this regresses.

## Surface

- Dashboard: `billing` tab in `Settings.vue`, shown only when billing enabled and
  role is owner/admin (Organization-tab pattern). Plan, two usage bars, Upgrade,
  Manage billing.
- Ingestion routes, `RequireRoleIfCloud("admin")`, 404 when billing off:
  `GET /billing/summary`, `POST /billing/checkout`, `POST /billing/portal`.
  All payment UI is Stripe/Autumn-hosted; we render none. Cloud deployments enforce
  the admin role. On self-host, any authenticated user may open checkout or the
  customer portal for the deployment's single org. This matches the existing
  self-host trust model: every authenticated user is effectively an operator, and
  any card entered belongs to that org.
